# Shared technical rules

These rules apply to all features (see the Technical Plan in Independent Work 3, Step 11).

- **Money and quantities.** All money uses C# decimal; double and float are never used for money (NFR-006). Unit prices (material price, labour rate, in the catalog and in estimate lines) are stored as DECIMAL(18,4); norms (consumption norm, labour norm) as DECIMAL(18,6); quantities as DECIMAL(18,3); percentages as DECIMAL(5,2). Calculated amounts are not stored. Validation rejects values with more decimal places than their column and never rounds them; norms and quantities have separate rules (BR-017, feature 016).
- **Rounding.** One helper (MoneyRounding) rounds money with decimal.Round(value, 2, MidpointRounding.AwayFromZero), so 0.005 becomes 0.01 (BR-017). .NET’s default rounding is banker’s rounding and is not used. Each line cost, overhead, profit and VAT is rounded; the grand total is the sum of the rounded parts; quantities and norms are not rounded in calculations. A work line's unit price (amount ÷ quantity, FR-032) is rounded by the same helper and is display-only.
- **Estimate calculation.** BR-015–BR-017 in docs/requirements.md: labour cost = quantity × labour norm × labour rate; material quantity = work quantity × consumption norm × (1 + waste %/100); material cost = material quantity × price; direct costs = sum of labour and material costs; overhead, profit and VAT are applied sequentially (profit on direct costs + overhead, VAT on direct costs + overhead + profit). The worked example in specs/007-estimate-creation-and-calculation/spec.md (1263.26 €) is the reference test. The Labour / Materials / Machinery split (FR-031) is calculated in EstimateCalculator from each material line's copied kind; overhead, profit and VAT stay on the direct costs as in BR-016.
- **Material kind.** A fixed list (Material, Machinery) defined once on the server (FR-030); new and existing materials and estimate material lines default to Material.
- **Percentages.** Overhead, profit, VAT and waste percentages are validated on the server to be between 0 and 100 inclusive (BR-007), independently of the frontend, and each has its own automated test.
- **Fixed measurement units.** The list (vnt., m, m², m³, kg, t, l, val., kompl.) is defined once in server/SmartEstimatePlatform.Api/Models/Entities/MeasurementUnit.cs (BR-008). Services validate against it and the frontend loads it from GET /api/units instead of duplicating it.
- **Destructive actions.** Every delete or remove action (material, work, project, work line, Viewer) and the estimate confirmation use the shared ConfirmDialog component (NFR-011).
- **Authentication model.** JWT Bearer authentication is the model chosen for this project; the user behind a token is checked on every request.
